Systo / three.js scroll sites

Stop drawing when nothing moves

One ticker fixes phase drift between Lenis, GSAP and the renderer. It does not stop you drawing sixty identical frames a second at a dead stop.

This page runs the ref-counted render governor. Watch the panel: scroll and it takes a hold, so the mode flips to continuous and the frame counter climbs. Stop, and the counter freezes.

Measured elsewhere: 43-74% CPU at rest from roughly 31 infinite CSS animations.
Holds, not counters

Identity keyed

Holds live in a Set of owner ids, never an integer. A module that double-holds or double-releases cannot corrupt the mode, and the diagnostics read like a story instead of a number you have to trust.

Every per-frame animator holds for exactly the lifetime of its animation. Discrete mutations, a slider write or a texture swap, request a single frame instead.

The verification

Measure it at rest

Focus the tab, touch nothing, and read idle GPU and CPU. If it is not near zero, something is holding. Dump the holds list and find the owner that never released.

A green build tells you nothing here. Only the idle measurement does.
